### 🏗️ Архитектура проекта: Краткая выжимка (High-Level Overview)

Наш проект реализует полностью автоматизированный цикл доставки ПО (CI/CD) и управления инфраструктурой с использованием концепции GitOps.

**1. Фундамент и Кластер (Day 0 - Уровень ОС)**

* 
**Инструмент:** Ansible.


* 
**Суть:** Кластер Kubernetes разворачивается локально на 3 master-узлах. Ansible подготавливает операционные системы и устанавливает K3s, интегрируя API-сервер с внешним провайдером авторизации (Keycloak).



**2. Инфраструктура как код (Day 1 - IaC)**

* 
**Инструмент:** Terraform.


* 
**Суть:** После создания кластера Terraform разворачивает все системные компоненты: распределенное блочное хранилище Longhorn, операторы баз данных (CloudNativePG), S3-хранилище (MinIO), систему GitOps (Argo CD) и настраивает ролевую модель доступа (RBAC), безопасно инжектируя секреты из GitHub среды.



**3. Непрерывная интеграция приложения (CI)**

* **Инструмент:** GitHub Actions + Docker Hub.
* **Суть:** При обновлении исходного кода разработчиками пайплайн собирает новый Docker-образ, пушит его в реестр и автоматически делает системный коммит в Git, обновляя тег образа в манифестах Kustomize.

**4. Развертывание и GitOps (CD)**

* **Инструменты:** Argo CD + Argo Rollouts.
* **Суть:** Argo CD выступает "контроллером состояния". Он непрерывно следит за Git-репозиторием. Заметив изменение тега от CI-пайплайна, он применяет манифесты в кластере. Выкатка происходит без даунтайма с использованием Canary-стратегии (с паузами и анализом HTTP-метрик).



**5. Данные, Бэкапы и Мониторинг**

* 
**Хранение:** База данных Postgres работает в отказоустойчивом режиме под управлением оператора, запрашивая персистентные диски (PVC) из Longhorn.


* **Disaster Recovery:** Резервные копии БД создаются автоматически средствами CloudNativePG. Архивация файлового S3-хранилища MinIO реализована через полностью самописный ресурс (CRD)  и CronJob-контроллер.


* 
**Observability:** Инфраструктура покрыта метриками и логами через стек Kube-Prometheus (Grafana) и Loki.



**6. Безопасность (Security Best Practices)**

* Сеть кластера сегментирована политиками `NetworkPolicy` (Default Deny All).


* Контейнеры защищены контекстом безопасности (`runAsNonRoot`).
* Доступ пользователей управляется через группы Keycloak, что обеспечивает принцип минимальных привилегий (Least Privilege).
